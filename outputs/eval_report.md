## 2 · Measured routing thresholds

Thresholds are read off the observed cross-encoder score distribution on this corpus. They are not carried over from a previous project: a different corpus produces a different distribution, and reusing a number across the two is how routing silently degrades.

**How the two populations were built.** Positives are the gold chunks of answerable questions. Negatives are every chunk retrieved for a *control* question — a question the corpus cannot answer at all. Taking "non-gold chunks retrieved for an answerable question" as the negative population instead would be badly contaminated, because a chunk that was not listed as gold is very often still relevant. The controls have no correct answer anywhere in the corpus, so every chunk retrieved for them is a genuine negative.

Balanced-accuracy peak at **tau = 0.33** (92.6%).

| Threshold | Value | Derived from | Used for |
|---|---:|---|---|
| `TAU_LOW` | 0.378 | p95 of the control population | below this, refuse |
| `TAU_HIGH` | 0.804 | p25 of the gold population | above this, answer directly |
| `TAU_VERIFY` | 0.152 | p75 of the control population | groundedness floor for a cited sentence |

Between `TAU_LOW` and `TAU_HIGH` the agent asks a clarifying question rather than guessing.

> **Stated plainly: these thresholds are tuned, not learned, and the positive population is small.** They are derived from the same question set the routing is later reported on, so route accuracy measured against them is optimistic by construction. The sweep above is published so a reader can see how much the choice actually matters rather than taking the point estimate on trust.

## 3 · Reproducing this

```bash

research-agent index      # bge-m3 vectors + FTS5
research-agent labels     # validate gold labels against extracted text
research-agent eval-retrieval
```

No API key is required for any of it.
